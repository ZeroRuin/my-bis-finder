# Weekly Wiki data updates

`.github/workflows/weekly-wiki-data.yml` checks the OSRS Wiki DPS Calculator's published equipment, monster and spell JSON every Friday at 04:17 UTC (Friday afternoon in Adelaide). It can also be run from Actions → Weekly Wiki data update → Run workflow.

The job uses GitHub's built-in token, needs no custom secrets, and makes no requests to the Wiki. In repository Settings → Actions → General → Workflow permissions, **Allow GitHub Actions to create and approve pull requests** must be enabled for PR creation. The workflow never approves or merges PRs.

The updater pins every download to one upstream main commit, checks numeric schema and record-count changes, skips equivalent content regardless of formatting/order, and refuses older per-file upstream snapshots. The legacy snapshot date is used as the initial conservative cutoff. All files are downloaded/validated before local writes. A failed download, malformed schema or >20% count change fails the job instead of publishing data. Unknown/new fields are retained for review.

Changed data must pass `gradle mechanicsSelfTest` before one reusable `automation/wiki-data-update` PR is created or refreshed. This branch is owned by automation; do not add manual commits to it. No changes means no commit/PR. Existing open update PRs remain open until reviewed; no-change runs do not close them. The PR identifies the upstream commit and changed record counts; the manifest records per-file provenance and SHA-256 hashes.

Upstream regeneration also uses review PRs, so the published main files may lag game changes. Spell JSON is published but is not regenerated by upstream's weekly equipment/monster workflow. Weekly checking cannot guarantee fresh upstream data or implement new combat mechanics.

Merging a data PR updates bundled data for a future plugin release; it does not update installed plugins or the current Plugin Hub submission automatically. Review attribution and existing dataset notices alongside data changes. This setup changes automation only, leaving the bundled v0.9.3 data intact.

GitHub schedules can be delayed and public-repository schedules can be disabled after inactivity. Check failed workflow notifications and the Actions page. No new ChatGPT reminder is required; this schedule runs in GitHub.
